# Цифровая платформа ФСП Оренбургской области

Единая платформа для регионального отделения Федерации спортивного программирования: учёт спортсменов, тренеров, судей, календарь соревнований, заявки, результаты, протоколы, разряды, рейтинг, сборная и отчёты.

## Требования

- Node.js 22+
- npm

## Стек

**Бэкенд:** Node.js 22+ и Express - HTTP-сервер, роуты, статика.

**База данных:** SQLite через better-sqlite3 - встраиваемая база в одном файле, без отдельного сервера.

**Тесты:** встроенный `node:test` - запуск через `node --test tests/*.test.js`.

**express** - HTTP-фреймворк. Маршрутизация запросов, middleware, раздача статики.

**better-sqlite3** - драйвер SQLite. Синхронные запросы без ORM, параметризованные, защита от инъекций.

**bcryptjs** - хеширование паролей. В базе только хеш с солью, восстановить пароль нельзя.

**jsonwebtoken** - JWT-токены. Выдаёт подписанный токен после логина, срок 24 часа, проверяется на каждом запросе.

**cors** - разрешает запросы с фронтенда на другом порту в dev-режиме. В production отключается, так как фронт и бэк на одном домене.

**docx** - генерация Word-файлов: протоколы соревнований, отчёты по спортсменам, списки сборной, проект приказа.

**exceljs** - генерация Excel-файлов: отчёт о численности с разрезами по годам, организациям, дисциплинам.

**node-cron** - планировщик. Раз в день проверяет сроки разрядов и судейских категорий.

**dotenv** - загрузка переменных из `.env`. Секреты (JWT_SECRET, путь к базе) не попадают в код и git.

**multer** - загрузка файлов с клиента. Используется для положений соревнований и сертификатов РУСАДА, файлы сохраняются в `uploads/`.

**nodemon** (dev) - автоперезапуск сервера при изменении файлов.

## Быстрый старт

### Linux / Windows
```bash
npm install
cp .env.example .env
npm run dev
```

## Структура

Папки:

**`routes/`** - все API-эндпоинты платформы, по одному файлу на домен: авторизация, справочники, соревнования, заявки, результаты, судьи, разряды, реестр, рейтинг, отчёты.

**`auth/`** - проверка доступа: чтение токена, сверка активной роли с базой, функции проверки прав и владения объектом.

**`db/`** - работа с базой данных: подключение, создание таблиц, заполнение демо-данными при первом запуске.

**`documents/`** - генерация файлов для скачивания: протоколы, отчёты, списки сборной в форматах docx и xlsx.

**`workers/`** - фоновые задачи: проверка сроков действия разрядов и категорий, автоматически подключаются при старте.

**`tests/`** - тесты на ключевую логику: авторизация, права доступа, проверка возраста, расчёт рейтинга, регистрация.

**`docs/`** - документация: описание API для фронтенда и структура базы данных.

**`public/`** - собранный фронтенд, раздаётся сервером как статика.

**`uploads/`** - файлы, загруженные пользователями (положения соревнований), в git не попадают.

Корневые файлы:

**`server.js`** - точка входа: подключение Express, регистрация роутов, раздача статики, обработка ошибок, корректное завершение при остановке.

**`package.json`** - зависимости проекта и скрипты запуска (`npm run dev`, `npm start`).

**`.env.example`** - пример переменных окружения (порт, секрет для токенов, путь к базе).

**`.gitignore`** - список того, что не коммитится: `node_modules`, файл базы, `.env`, загруженные файлы.

**`README.md`** - инструкция по запуску, тестовые аккаунты, описание структуры и реализованных сценариев.

**`db.sqlite`** - файл базы данных, создаётся автоматически при первом запуске, в git не коммитится.
